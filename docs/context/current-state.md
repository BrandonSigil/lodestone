## How to run it
1. Install Godot 4.4 or newer (4.7.2 works; don't commit Godot 4.7's rewrites of existing project files).
2. Open `game/project.godot`. F5 opens the launch menu (`scenes/launch.tscn`): one button per built place. **New game** starts the E2E loop from a fresh save in the hero's cottage, **Continue** keeps the save; the rest fast-travel to the village hub, trail, world map, each explore map, the trail fight and the sandbox.
3. Anywhere in the game: **F7** launch menu, **F8** map maker, **F9** combat sandbox, **F10** walkable exploration map. In the editor, F6 runs the open scene.
4. Checks: `GODOT=/path/to/godot tools/check.sh` (headless import, about 130 unit tests, smoke runs of launch, village, trail, combat, world_map, combat_sandbox, explore and map_maker). Run it after every change.
5. Screenshots: `tools/screenshot.sh`, `game/tools/explore_shot.gd`, `game/tools/sandbox_shot.gd`, `game/tools/map_shot.gd`, `game/tools/maker_shot.gd` (in the cloud: `xvfb-run` and `--rendering-driver opengl3`). On the Mac, run every windowed Godot call through `tools/godot.sh <args>` (e.g. `tools/godot.sh --path game -s res://tools/explore_shot.gd -- out.png start`): the window opens on the laptop display and focus returns to Brandon's app, so his full-screen Space on the main monitor doesn't flip. `GODOT_SCREEN` picks another display.

## The art recipe that works now
- Model: GPT image (`gpt-image-2.5-sunburst`) through the Picsart API on the MacBook, about 10¢ per sheet at 2K. Flux is cheaper but copies references too literally.
- Character sheets default to **1K** (5.5¢) through `tools/art/char_sheet.py`: the cutter shrinks every sheet to sprite size, so 1K and 2K look the same in game (tested on the lead's S facing). A hero's five facings times two sheets is about 55¢; a combat-only enemy (SE, NE) 11 to 22¢. Tile kits, maps and village art stay at 2K.
- Look: Brandon loves the SIMPLE flat style: near-solid grass with a few dots, two-tone blob trees, three flat values, plain one-colour cliffs. "Too detailed" is his recurring complaint.
- Reference images: his approved flat forest panel (`docs/art/references/style-flat-forest.png`) plus its tile-row crop for tile kits. Attach only those. Never feed a result back in as a reference; detail compounds.
- Picsart's credits endpoint reads 0 even when the dollar wallet has money; `picsart_sheet.py` no longer stops on it.

## Gotchas for Claude sessions
- `tools/check.sh` finds Godot on PATH or at `/Applications/Godot.app/Contents/MacOS/Godot`, and fails if it finds neither (it used to pass silently with no tests run).
- Auto fights (`Battle.auto_fight`) end in a stalemate as a win after a while with nobody hurt, so the game moves on as if won. The E2E robot counts that as a failed check, on road fights and explore fights alike; it is not a fall (the old seed 3 "hang" was this).
- `CombatBoard` draws through child "slab" nodes; every draw helper paints on `_ci` (the slab being drawn). A `draw_*` call on `self` from those helpers fails. Ground and props are cached per depth row; `grid.version` and the fog tell the board what to redraw.
- Godot in the cloud rewrites every art `.import` file; `git checkout -- game/art` before committing. Godot 4.7 on Brandon's machines edits project files too; don't commit those edits.
- Godot's editor setting Text Editor > External > Use External Editor must stay OFF on the Mac. It was on, with Godot itself as the external editor, so every time the open editor (or a headless import) wanted to show a script it launched a second Godot as `<game dir> --goto <file>`, which opens the Project Manager on Brandon's main display and takes focus (2026-10-29: eight stray windows, all on `combat_board.gd`). `tools/godot.sh` can't catch these.
- The MacBook has no git-lfs (PNGs go in as plain blobs) and a big art push dies with "unexpected disconnect"; push with `git -c http.postBuffer=524288000 push`. Godot there is `/Applications/Godot.app/Contents/MacOS/Godot` (4.7.2).
- Picsart (picsart.io) is blocked from the cloud container, so API runs happen on the MacBook through Remote Control.
- `save_psd` in `tools/art/battle_art.py` must build an RGBA PSD, or psd-tools hides strokes behind a layer mask.
- GDScript errors on type inference from Variant; use explicit types or `int()`.
- Autoloads don't `_ready` before a `-s` test script; tests call `Db.reload()`. A `-s` script that names game classes fails to compile; load a helper at runtime (see `game/tools/sandbox_shot.gd`).
- Full `balance_report` at 100 fights takes about 8 minutes.
- On the MacBook, a screenshot or frame-capture run whose window sits behind other apps can stop rendering (macOS pauses it), so animated frames come out identical. Pass `--always-on-top` to Godot for frame captures.
- Several threads push to main at once. Pull often, keep PRs small, and don't edit shared render code (`CombatBoard`) without checking what other open work touches it.
